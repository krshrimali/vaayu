# Pending audit follow-up — 2026-10-11

The pending editor features from the October 10 audit are implemented. Real-clangd verification is also complete using an isolated matching LLVM dependency. Baseline: `858e832`.

## Changes

- `%` now matches nested `()`, `[]` and `{}` across lines, accounts for quoted/escaped brackets and C comments, matches C comment boundaries, and navigates nested `#if`/`#else`/`#elif`/`#endif` conditionals. `1%` through `100%` jump to a file percentage. Normal, Visual and operator commands share the motion; successful jumps enter jump history, and failed operators preserve the previous dot-repeat.
- Visual-block `p`/`P` now replace the selected rectangle. A single characterwise line repeats down the selection; multiline characterwise text is inserted once; a block register keeps its own row count and width; linewise text goes below (`p`) or above (`P`). Counts, named registers, short/empty rows, reversed selections, partial tabs/wide characters, EOF extension and `$` across unequal rows are covered. `p` records the removed rectangle as a block register; `P` preserves the source register. Each replacement is one undo transaction. `.` repeats the rectangular replacement, including a count override.
- `:e! filename` and `:edit! filename` now reload an already-open target. PTY testing exposed that they previously switched to stale in-memory text even after the disk file changed. The regression also checks buffer identity, clean state and cleared undo history.
- The existing real-clangd Rust test now verifies an actual error diagnostic, formatting and saving. A new PTY test checks diagnostics, explicit formatting and format-on-save at three terminal sizes. CI runs both new PTY drivers for both binary names.

## Verification

Both release binaries build with the lockfile. Rust formatting and strict Clippy pass. The clean-checkout Rust suite passes **868 tests per binary**, with three ignored; the expanded real-clangd test passes explicitly for both binaries.

The final release run passes **20 PTY suites, 5,834 assertions and 11,212 keyboard input sequences** across `vaayu` and `vy`. Overall evidence records 12,321 input sequences and 12,287 terminal frames; exploratory/debug failures are excluded from the final release totals. An input sequence is one submitted batch of keys, potentially containing a whole Vim command or queued burst; assertions and individual characters are not counted as separate operations.

The committed reference fixture has **120 direct block-replacement cases and 94 matching/percentage-motion cases** generated with the installed Vim. Rust checks text, character cursor positions, register contents/types, named-register preservation and undo/redo. The full PTY matrix repeats directly seedable cases at 40x12, 100x24 and 180x50, adds five explicit repeat cases, and checks saved text and cursor positions. CI uses a representative subset; `VAAYU_PENDING_FULL=1` enables the full driver.

Additional release regressions exercise Unicode history and Visual repeats, Vim editing boundaries, multiple cursors, text objects, persistent undo, sidebar focus and tour focus. Projects, config/data directories and register source files are temporary fixtures. Clipboard access is disabled in the new tests. No GitHub remote mutation was performed in this follow-up.

## Compatibility and environment notes

- The installed Vim 9.2 build repeats only the deletion when `.` follows a Visual-block put. Four independent interactive sessions confirm this, including actual yanks and named/unnamed `p`/`P`. Vaayu deliberately repeats the replacement, preserving the source for `P` and reading the current register for `p`. These repeat cases are explicit behavioral tests rather than claimed Vim parity passes. Raw batch and interactive reference results are retained.
- The initial multicursor run inherited `NO_COLOR`, which suppresses reverse-video styling. Its styling assertion failed on both the baseline and new binary. Repeating with `NO_COLOR` unset passes; only the corrected run enters the final release totals.
- Vim's `charcol()` omits composing characters; the oracle uses `strchars()` up to the byte cursor to compare Vaayu's character-based cursor columns correctly. This affected the reference harness, not editor behavior.
- `/usr/bin/clangd` is version 22.1.8, while the system LLVM library is version 23. Its normal launch still needs the matching LLVM 22 library. Tests extract `libLLVM.so.22.1` from the cached `llvm-libs-22.1.8-2-x86_64.pkg.tar.zst` into a temporary directory and use a wrapper with `LD_LIBRARY_PATH`. No system packages or editor configuration are changed. Actual clangd diagnostics, formatting and saves pass with that dependency available.
- Earlier documented no-op undo policy differences and unusable Vim wide-character reference results remain compatibility/oracle limits. They are separate from the completed pending features. Custom Vim `matchpairs`, `cpoptions` and matchit plugins are outside this editor's configuration model.
