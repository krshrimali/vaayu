# Third UI audit — 2026-10-10

Further testing covered Unicode editing, Visual repeat, undo/redo and the interaction paths from the earlier audits. The baseline was `0f3d11f`; all projects, clipboard providers and GitHub mutations used temporary fixtures.

An operation is one submitted keyboard or mouse sequence, which may contain a complete Vim command or a burst of queued chords. Assertions and individual characters are not counted as separate operations.

This round recorded **43,230 input sequences**: 32,372 in Vaayu, 10,723 in `vy`, and 135 in interactive Vim. There are 43,062 captured terminal frames. These totals include exploration and failed preliminary harness attempts; the final release verification is counted separately.

**Final release verification: 11,045 UI sequences, 33 passing driver runs and 15,455 passing assertions across both binaries.** Each binary passes 560 main Vim text/cursor comparisons and 84 additional script-class comparisons, with 24 documented policy exceptions and four quarantined Vim reference results. There are no unexpected differences in the final matrix. Thirteen defect categories were fixed.

## Fixed findings

`<C-v>` means Ctrl-V, `<C-r>` Ctrl-R and `<Esc>` Escape. Commands start at `gg0` unless stated otherwise. Cursor columns below refer to characters; rectangular ranges use display cells.

| ID | Reproduction / previous behavior | Result |
| --- | --- | --- |
| H1 | Delete, move with `$`, undo, redo: redo used the later live cursor. Empty-line `dwu<C-r>` also landed on the following indentation. | History retains the command's change position, including backward operators and insert entry points. |
| H2 | `x$uj` or `x$u<C-r>j` on tabbed/Unicode rows kept the old desired column. | Undo and redo re-anchor vertical motion to the restored cursor. |
| H3 | `xxx2u` ignored the count; counted Ctrl-R also replayed one step. | Counts apply to undo and redo until the available history ends. |
| V1 | `vlcQ<Esc>dk.` / cancelled `d<Esc>` discarded the previous Visual-repeat dimensions. | Failed and cancelled operators preserve the last successful Visual edit. |
| V2 | Visual `.` used character counts for tabs/wide glyphs and could cut a different range. | Repeat stores display widths and converts them back to grapheme boundaries. |
| V3 | Visual repeat ran with Normal operator semantics, losing a selected newline; sticky `$` repeat also became a fixed-width edit. | Repeat preserves Visual selection semantics, newline inclusion and end-of-line intent. |
| B1 | `<C-v>jAQ<Esc>` on rows beginning with tabs could insert before the tab and fail to replicate. Wide glyph endpoints had the same width error. | Block A uses the complete selected display width. |
| B2 | Block I/A left the cursor on the typed text rather than the original top-left edge. | Typed block edits retain the original character column for the return cursor; no-input I keeps the normal Escape leftward step. |
| B3 | A block edge cutting through a wide glyph discarded the unselected half, or yanked a whole glyph outside the rectangle. | Partially selected wide glyphs become spaces for the selected and retained cells. Case changes preserve the full glyph. |
| B4 | Block insertion on subsequent rows floored inside tabs/wide glyphs and could derive the copied text from the wrong first-row column. | Replication uses the recorded insertion start and prepares each display-cell boundary independently. Untouched tabs remain intact. |
| B5 | `$` plus vertical block motion selected the wrong end cell. Block I/A padded or appended at the wrong column on unequal rows. | Block EOL intent uses the virtual newline boundary; I caps on short rows and A follows each row's end. |
| B6 | Block C with its left boundary inside a tab put the replacement after the retained prefix space. | The first-row insertion uses the original character column; later rows retain rectangular alignment. |
| U1 | `dw`/`diw` split combining accents from their base, while mixed Latin/CJK text was treated as one small word. | Word motions and text objects share combining-aware classes and separate common East Asian script runs. `W` keeps big-word behavior. |

## Verification

The committed PTY regression covers three terminal sizes: 40x12, 100x24 and 180x50. Rust formatting and strict Clippy pass. The complete clean-checkout Rust suite passes 863 tests per binary, with three ignored. Both release binaries build with the lockfile. Eight new Rust regression tests cover multiple independent history, repeat and Unicode examples; CI runs the new PTY driver for both executable names.

The final matrix repeats rapid Ctrl-W directions (including held Ctrl and zero-delay input), GitHub workflows and checkout/error races, tour focus, floating-terminal borders, mouse split resize, delayed/disconnected LSP requests, persistent undo and normal UI workflows. GitHub write operations are fixture tests. This round did not mutate a real remote or replace the desktop clipboard.

The installed `/usr/bin/clangd` still fails before initialization because `libLLVM.so.22.1` is missing. A real PTY startup/restart test confirms that Vaayu reports the exit and continues to edit/save. Successful real-clangd formatting remains unverified on this host; mock-LSP success, timeout, stale-response and disconnect paths pass.

## Remaining differences and limits

- `%` bracket matching and paste over a Visual block are still unsupported commands. PTY checks confirm their current behavior; they are feature gaps, not claimed fixes.
- 24 of the 588 differential cases depend on an empty/no-op `x` interacting with seeded undo/redo history. Vaayu intentionally omits no-op undo entries and retains redo, as documented by `Buffer::commit_edit`; Vim behaves differently. These cases remain explicit compatibility exceptions, including their cursor effects.
- Four cases make the installed Vim produce invalid UTF-8 when block A cuts a wide glyph. Interactive Vim reproduces this. They are quarantined as unusable reference results; they are not counted as parity passes or editor defects.
- Block A with no typed input can still pad its first row or copy a boundary tab. Both batch and interactive Vim confirm this behavior; it is preserved and covered by the new regression.
- A 40 ms terminal-drain sample briefly observed an old cursor frame. A direct editor regression and the longer final PTY drain verify the actual Unicode redo/vertical position. Harness failures (an Escape/Alt ambiguity, stale build run, missing fixture variable and an initial clean-checkout copy error) are retained in evidence and excluded from final verification claims.
- No claim covers all Unicode scripts/grapheme clusters, arbitrary terminal implementations, SSH/tmux clipboard integration, or every GitHub service/network failure.
