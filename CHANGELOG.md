# Documentation change coverage

## Mouse everywhere, right-click menus, clickable breadcrumbs — 2026-11-25

The mouse now works in buffer text as in desktop editors. A double click selects a word and a triple click the line; dragging on after either extends by whole words or lines. Shift-click extends the selection from the cursor or its anchor, Alt-click adds a cursor (or removes the one there), and a plain click collapses extra cursors. Pressing on the line numbers selects lines and dragging there extends them; a click on the fold column toggles the fold. A drag that leaves the pane above or below scrolls it a line per movement, so a selection can grow past the screen, and a drag no longer jumps into the pane it crosses. The tabline takes clicks (middle-click closes a tab).

The right button opens a context menu for what is under it, drawn over everything and driven by keys (`j`/`k`, Enter, `l`/`h` for submenus, Esc) or the pointer (hover, click, or release a right-drag on an item). Over text it holds go to definition, references, peek and the other LSP jumps, rename, code actions, format, cut/copy/paste/select all through the system clipboard, copy GitHub permalink, open on GitHub, copy path, git (blame, preview/stage/revert change), find/replace in files, add cursors to all occurrences, review comment and send to agent. Clicking inside a selection keeps it, and the items act on it. The file tree, tabline, winbar and terminal panes have their own menus. Each item runs an existing action, key sequence or Ex command. `Editor::permalink_url` builds the link without copying it, for "Open on GitHub".

Breadcrumbs (the winbar) are on by default. They show `folder › file › outer symbol › inner symbol`, with symbols named from the tree-sitter `name` field (`fn draw`, `impl Widget for Pane`), and drop folders from the left behind `…` when narrow. A folder opens a dropdown of its entries, the file name the file's top-level declarations, and a symbol its siblings, with the current one selected. The path is cached per buffer line and recomputed only when the cursor changes line or the buffer is reparsed; while a deferred parse is pending the line keeps its path. Unfocused panes show their own path while their buffer is unchanged. The `%C` statusline item shares the cache. The scroll-region fast path, which repaints scrolled frames by moving rows, now works below the winbar instead of being turned off by it. See [the menu](src/menu.rs), [breadcrumbs](src/breadcrumbs.rs), [mouse](src/mouse.rs), [the renderer](src/render.rs) and [syntax](src/syntax.rs).

## Review screen for agent worktrees — 2026-11-24

`:worktrees` lists the repository's Git worktrees with what each was made for: the record an agent leaves in `code-reviews/<slug>.json` at the main checkout's root (title, description, base commit, status, notes, revisions), or the branch's `git branch --edit-description` text. Enter switches the project to the worktree and opens the review screen. The `review-worktree` Claude skill writes the worktree and the record.

`:reviewstart [REV]` is the review screen: a table of contents of the files changed since the base (Git status, path, `+added −removed`, open comments; untracked files included) pinned beside the code, at the edge `review_toc` names, movable with `:reviewtoc left|right|top|bottom`. Enter or a click opens a file at its first change. Lines the change left alone are dimmed, and the cursor line and the line under the mouse pointer are lit; signs, changed words and removed lines compare with the base. `]F`/`[F` step files, `]c`/`[c` step changes against the base, `:reviewhunk` shows removed lines. The table re-reads `git diff` every four seconds while open. `:reviewcopy` copies the open comments with their code as a prompt for the agent. The layout gained fixed-height top and bottom panes for the table. `git_branch` now reads a linked worktree's `HEAD`, so reviews started there are named after its branch. See [the review screen](src/review_toc.rs), [worktrees](src/worktrees.rs), [the renderer](src/render.rs) and [the regression tests](src/regression.rs).

## Copying agent output, clickable ranges and names — 2026-11-23

Agent output can be copied with the mouse: drag over an agent pane (or any terminal pane whose program does not take the mouse) to select and copy to the clipboard and the `+`/unnamed registers, double-click to copy a word, triple-click a line. Before, the editor's mouse capture made the text impossible to select. `yy`, `Y`, `3yy` and `y{motion}` on a terminal pane in Normal mode now yank from the captured output at once; the first `y` used to open the capture and the second wait for a motion, so nothing was yanked.

Clickable output covers more. Line ranges (`a.rs:12-20`, `a.rs:12–20`, `a.rs#L12-L20`, `a.rs (lines 12-20)`, `lines 12-20 of a.rs`) open with the lines selected linewise. Directories are revealed in the file tree. Names defined in the workspace (functions, classes and types, modules, constants, struct and interface fields, top-level variables) open their definition: a background index finds them with per-language patterns, needs no language server, and the file watcher keeps it current. A name with several definitions prefers the file the agent mentioned nearby, otherwise a list opens. Only names that read as code are links (`snake_case`, `camelCase`, `Name::qualified`, `call()`, backticked, or a capitalised type name), so prose stays plain. Links now open on release, so a drag that starts on a path selects it. See [the symbol index](src/symbols.rs), [selection](src/termselect.rs) and [links](src/termlinks.rs).

## AI Focus switches tabs — 2026-11-23

The `:ai` picker's Focus entry, `:aistart`, and Enter in `:agents` now switch to the tab that already shows the agent, rather than opening a second pane onto the same session in the current tab. `:agents` labels such a session "open in tab N". An agent that isn't shown in any tab still opens in the current one. See [PTY](src/pty.rs).

## Several AI sessions, clickable agent output, smooth scrolling — 2026-11-23

`:ainew [instruction]` starts another session of the configured agent beside the running ones (`claude #2`, `claude #3`, numbered on each pane's statusline and in `:agents`). New sessions stack in the agents' column, so the code keeps its width. `:ai`, `:aistart`, `:aistop` and `,cx` act on the agent pane you focused last; `:aistop!` stops them all, and the `:ai` picker has a New session entry. Prompts queued for sessions still starting are kept per session, so two at once no longer overwrite each other.

Output in agent and terminal panes is clickable, as in Cursor's chat. A file reference (`src/a.rs`, `src/a.rs:12:5`, `Update(src/a.rs)`, `a.rs#L12`, `File "a.py", line 3`, or a bare `pty.rs:857` that names one project file) opens in the editor pane next to the agent, on that line and centred. If there is no editor pane, one is split off. A row of a diff the agent printed opens its file at that line: Claude Code's `  12 +  code` under `⎿ Updated src/a.rs`, Codex's `• Edited` blocks, permission boxes, and `git diff` hunks (counted from the `@@` header). URLs open in the browser. The link under the pointer is underlined. `Ctrl-W p` returns to the agent. A non-agent program that takes the mouse itself, such as lazygit, keeps plain clicks; Ctrl-click opens links there.

Scrolling in terminal panes is eased. The wheel and `Ctrl-u`/`Ctrl-d`/`Ctrl-b`/`Ctrl-f` move the first step at once and play out the rest over a few frames. `smooth_scroll = false` turns this off. See [links](src/termlinks.rs), [PTY](src/pty.rs), [mouse](src/mouse.rs), [the regression tests](src/regression.rs) and [the PTY test](tests/pty_ai_links.py).

## AI pane split direction — 2026-11-23

Agent panes (`:ai`, `:aistart`, `:airestart`, `:claude`, `:codex`, `:agent`, and reattaching from `:agents`) can now open below instead of to the right. The new `ai_split` setting (`"vertical"` by default, or `"horizontal"`) picks the direction, and `:vert` or the new `:hor` / `:horizontal` modifier picks it for one command: `:hor ai Explain this`, `:vert claude`. `:hor ai` with no prompt carries the direction to whichever picker entry you choose. A range or Visual selection typed before the modifier (`:'<,'>hor ai`) still goes to `:ai`. An agent that is already open is focused where it is, not moved. `:hor split`, `:hor new` and `:hor resize` work as in Vim. See [PTY](src/pty.rs), [Ex](src/command.rs) and [configuration](CONFIGURATION.md#ai-cli-selection).

## Word-under-cursor search — 2026-11-22

`*` and `#` search forward and backward for the word under the cursor as a whole word, and `g*`/`g#` also match inside longer words, as in Vim: the next word on the line is used when the cursor is between words, `#` from mid-word skips the word itself, a count jumps that many matches, the search lands in `/` history and `n`/`N` continue it. Before, these keys did nothing. See [normal mode](src/normal.rs) and [help](HELP.md).

## Persistent message log — 2026-11-22

Messages now persist across sessions. Each new message is appended as a timestamped, tagged line (`[msg]`, plus `[session] start`/`end`) to `vaayu.log` in the per-user state directory (`~/.local/state/vaayu/` on Linux), a private 0600 file rotated by size. `:Log` opens every logged line, including rotated files, oldest first, in a buffer; `:messages` still shows only this session's in-memory messages. New settings `persist_messages` (default on; `:set nopersist_messages` turns it off for the session), `log_max_kb` and `log_keep`. A write error turns logging off with one message and never interrupts editing. The log also records panics from any thread (`[panic]`, the message then the backtrace), language server stderr and `window/logMessage`/`window/showMessage` notifications (`[lsp:<server>]`), and one `[job]` summary line per finished `:make`/`:task`, test run, review agent run, git task and terminal or agent session: title, ok/failed, duration, and result or exit code, never the full output. See [the logger](src/log.rs) and [configuration](CONFIGURATION.md).

## AI sidebar and terminal panes — 2026-11-20

Terminal panes (the `:ai` sidebar, `:claude`/`:codex`/`:agent`, `:terminal`) now scroll: the wheel, Normal-mode `j`/`k`/Ctrl-U/D/B/F/`gg`/`G` and Shift-PageUp/PageDown move through history, typing snaps back, and `/`, `?`, `v`, `V`, `y` or `:termcapture` open the whole output in a buffer. Each terminal pane has a statusline (mode, name, exit status, scroll position). Keys keep their modifiers (Alt, Shift/Alt+Enter, Ctrl+arrows, F-keys); Ctrl-\ sends the next key literally, so Esc and Ctrl-W reach agents; programs that request mouse reports receive them; dim and italic text render. Clicking focuses or leaves a terminal pane, and a paste into the command line over one stays in the command line.

`:ai` from Visual mode with no instruction keeps the selection (it sent the whole file); characterwise selections are sent exactly; code fences carry the language and no stray blank line. New `--file`/`--selection`/`--diff`/`--buffers`/`--none` context flags, a "Review changes" template, `[[ai_prompts]]` custom templates, `ai_focus_on_send` (default on: the sidebar takes focus so Enter submits) and `ai_auto_submit`. Exited agents are shown as exited and restarted on next use instead of silently receiving prompts; `:aistart`, `:aistop`, `:airestart` and `:agentstop` manage sessions, and the picker offers Restart/Stop. Agent sessions always open as a right-hand sidebar. The AI, agents and context pickers no longer advertise multi-select, quickfix or review-agent keys. See [PTY](src/pty.rs), [context](src/context.rs), [mouse](src/mouse.rs), [the guide](GUIDE.md) and [configuration](CONFIGURATION.md#ai-cli-selection).

## Selectable statusline — 2026-11-18

Statuslines (per-pane, global, preview footer) and the message line can be selected with the mouse: drag to highlight and copy, double-click copies a word (such as the file path), triple-click the whole line. Copies go to the `+` register and so the system clipboard; the highlight stays until the next key or click. Before, the editor's mouse capture made that text impossible to select. See [the mouse code](src/mouse.rs) and `selectable_row` in [the renderer](src/render.rs).

## Review comments rework — 2026-11-16

Reviews are now named and a folder can hold any number of them (`:reviews`, `,rs`, `:reviewnew [--base REV]`, `:reviewswitch`, `:reviewrename`, `:reviewclose`/`:reviewreopen`, `:reviewbase`, `:reviewfiles`). Each is one file under `.vaayu/reviews/` at the Git work tree root, written through immediately and merged under a lock, so several editors share a review live and `#N` numbers are never reused. Version-1 `comments.json` notes are imported once.

Fixed: concurrent sessions could not save ("reopen before saving") and reused numbers; `:cd` split comments across folders; abandoned drafts were saved as empty comments and blocked `:q`; opening the list marked comments unsaved; a file comment marked every line; gutter marks did not follow edits until the list was reopened; identical lines could silently capture a comment; deleted files were not flagged; `:wq` in a comment quit the editor; agent failures, timeouts and cancellations all reported "finished"; agent output was unstructured and overwritten; review packets piled up.

Added: comments open in a split under the code with the lines tinted; colored gutter marks (`●` `│` `◌` `○`), comment text after the line (`:set reviewtext=`), status line counts and minimap marks; live anchors through unsaved edits and undo, with two lines of context for re-finding; `]r`/`[r`; `,rv` threads, `,rr`/`r` replies, `,rx`/`R` resolve, `,rm`/`m` re-anchor, confirmed delete; list sorted by file with open/attention/resolved/all views and code-then/code-now detail; version-2 agent packet with threads and current code, JSON Lines replies attached to comments (agents never resolve), jumpable findings that become comments with `c`, separate stderr, per-run history (`:reviewruns`), a running indicator, and process-group cancellation; `:reviewpublish` (pending GitHub PR review, out-of-diff comments in the summary) and `:reviewimport`. New settings `review_instructions`, `review_author`, `review_virtual_text`, `review_run_history`. See [the guide](GUIDE.md#private-review-comments), [store](src/review_store.rs), [editor side](src/notes.rs), [agent/GitHub](src/review.rs) and the [pty_review](tests/pty_review.py) suite.

## `:cd` and `:pwd` — 2026-11-02

`:cd [dir]` (alias `:chdir`) changes the working directory and switches the project root, so relative paths, the file picker, grep, the file tree and new terminals follow. No argument goes home, `~` expands, `:cd -` returns to the previous directory, and Tab completes directories only. `:pwd` shows the working directory. Switching the root, by `:cd` or `:projects`, now also discards the file index and the resumable picker; before, the picker kept listing the old project's files. See [the code](src/projects.rs) and the [pty_cd](tests/pty_cd.py) suite.

`cargo build --profile fast` gives an optimized binary at `target/fast/vaayu` without full LTO, for local work. Shipped builds keep full LTO. See [the commands](DEVELOPMENT.md).

## Command-line help — 2026-11-01

`vaayu --help` and `-h` print the usage, options, first steps, files, environment variables, optional tools and examples, then exit. Before this, `--help` opened a buffer named `--help`. See [the text](src/cli.rs).

## Browser editor — 2026-11-01

`vaayu --web [file]` and `:web [file]` open the full editor in a browser tab, with no extension, install step or external resources. The main loop now runs over a [`Frontend`](src/frontend.rs), so terminal and browser share dispatch, jobs and rendering; the terminal's behaviour is unchanged. `--host ADDR` can listen on a network address, with a warning because the connection is unencrypted. Added the `web_font_family` and `web_font_size` settings and the `tungstenite`, `getrandom` and `signal-hook` dependencies. See [the guide](GUIDE.md#browser-editor), [architecture](ARCHITECTURE.md#browser-frontend), [measurements](BENCHMARKS.md#browser-editor--2026-11-01) and the [web_ui](tests/web_ui.py), [web_server](tests/web_server.py) and [pty_web_launch](tests/pty_web_launch.py) suites, which run in CI.
