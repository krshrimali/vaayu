# UI audit — 2026-10-09

Completed **1,000 recorded UI operations**: **998 in Vaayu** and **2 in interactive Vim** to verify macro behavior. Testing started from `f543b4eb202301d0d76a97f02a8bcd99875f0649`. Six reproducible bugs were found, fixed, and verified. One additional Vim compatibility gap is recorded below.

The plan was written before execution: isolate fixtures and editor state; test editing/navigation and all implemented GitHub entry points through real PTYs; independently reproduce failures; verify fixes; stop at 1,000 operations. No questions or approvals were needed.

## Method and evidence

An operation is one deliberately submitted keyboard or mouse input sequence, commonly a complete Vim command. Inserted characters and command arguments are not counted individually. A sequence may contain a prefix and its continuation, or several related normal-mode commands. The ledger contains exactly 1,000 unique, consecutive IDs. IDs 993–994 are the Vim reference operations.

The audit contains 48 logged suite groups, including reproduction and fix verification. There are 967 rendered terminal snapshots; the remaining operations belong to tests using `pexpect` output assertions. Screens, cursor positions, saved files, local Git state, and fixture CLI arguments were checked. The initial 38 suites completed 660 operations with 482 assertions passing. The complete run recorded 686 passing assertions, plus comparisons of saved text and cursor position against Vim.

All projects, config, clipboard helpers, language-server fixtures, and Git repositories were temporary. GitHub responses came from a local `gh` fixture, including deterministic gates that hold checkout/list responses until the test releases them. This made races reproducible without changing a real GitHub repository.

[Raw evidence archive](artifacts/ui-audit-2026-10-09.tar.gz) contains the operation ledger, screens, results, driver scripts, comparison data, and verification logs. The individual evidence links below show representative terminal screens.

## Confirmed bugs and fixes

| ID | Severity | Bug | Result |
| --- | --- | --- | --- |
| B1 | High | Checkout completion discarded edits made while checkout was pending, including undo history. | Fixed: preserve modified buffers and undo history; flag disk changes and report preserved edits. |
| B2 | High | Another GitHub request dropped a pending checkout's completion receiver, leaving buffers stale after the branch changed. | Fixed: retain the checkout receiver and reject another GitHub job until it finishes. |
| B3 | Medium | Delayed GitHub results interrupted command input and visual selection. | Fixed: defer results while input, selections, other views, or multi-key commands are active; Ctrl-Q explicitly opens them. |
| B4 | Medium | Invalid explicit PR numbers silently selected the current branch's PR. | Fixed: reject invalid arguments before invoking `gh`. |
| B5 | Medium | HTTP/backend errors resolving the current PR were reported as “no pull request.” | Fixed: preserve the underlying error; classify only the actual missing-PR response as missing. |
| B6 | Low | Floating-terminal borders in `mono`, `warm`, and `cool` retained default cyan/grey colors and dark background. | Fixed: supply focused, unfocused, and floating-background colors from those palettes. |

### B1: unsaved edits lost during checkout

Start with clean buffers, run `:ghcheckout 5`, and type `iUNSAVED_MARKER<Esc>` while the request is waiting. Release checkout. Before the fix, the marker vanished as `reload_after_checkout` replaced every buffer. `u` could not recover it because reload also cleared undo history.

Reproduced in operations 822–824 and 859–865. [Before: lost edits](artifacts/ui-audit-2026-10-09/evidence/checkout-edit-loss.txt). The fixed run preserved the marker, displayed the preserved-edits message, and verified both undo and redo (939–950). [After: preserved edits](artifacts/ui-audit-2026-10-09/evidence/checkout-edits-preserved.txt).

The fix reloads clean buffers and preserves dirty ones. The editor marks preserved buffers as changed on disk, so the user can reconcile them with the new branch. A Rust regression also checks that clean buffers reload while the edited buffer retains undo.

### B2: checkout completion lost when another request starts

Hold `:ghcheckout 5`, run `:ghprs`, close the list, then release checkout. Before the fix, Git switched to `pr-5` and the file on disk changed, but the editor retained the old branch's text because the PR-list request had replaced `gh_task`.

Reproduced in 826–828 and 870–873 with `watch=false` and `autoread=false`, making the missing explicit reload observable without a watcher masking it. [Before: stale buffer](artifacts/ui-audit-2026-10-09/evidence/checkout-stale-buffer.txt). In the fixed run, the new request was refused while checkout was pending, and checkout reloaded the buffer (956–959). The Rust regression confirms the original receiver survives and its completion is processed.

### B3: delayed results steal an active editing mode

Hold a `:ghprs` response, then type `:set number` without Enter, or enter `vll`. Release the response. Before the fix, the PR list replaced command mode or visual mode, interrupting the command or selection.

Reproduced in 830–835 and 880–890. [Before: command interrupted](artifacts/ui-audit-2026-10-09/evidence/github-command-interrupted.txt). Fixed operations 985–991 preserve command input and the visual selection, then open the deferred list with Ctrl-Q. [After: command preserved](artifacts/ui-audit-2026-10-09/evidence/github-command-preserved.txt).

Rust regressions additionally cover Insert mode, an existing Results list, pending operators/counts, and a Ctrl-W prefix. Deferred results do not repeatedly redraw or restart the progress indicator.

### B4: malformed PR arguments select the wrong PR

Run `:ghpr garbage`, `:ghdiff garbage`, `:ghthreads garbage`, or `:ghchecks garbage`. Before the fix, each resolved the current branch's PR #5 and displayed its data instead of rejecting the input.

Reproduced in 811–817 and 839–849. [Before: invalid argument opens PR #5](artifacts/ui-audit-2026-10-09/evidence/github-invalid-number.txt). Fixed operations 907–919 display usage and assert that no `gh` subprocess started. Rust coverage also rejects zero, negative numbers, repeated `#`, multiple arguments, overflow, and invalid checkout arguments. Omitted arguments still mean the current PR; positive numbers and `#N` remain valid.

### B5: backend failures misreported as missing PRs

Make current-branch resolution return `HTTP 502: upstream temporarily unavailable`, then run `:ghpr`. Before the fix, the UI claimed no pull request existed. The generic `gh pr:` prefix caused unrelated backend and parsing errors to be rewritten.

Reproduced in 820 and 855. [Before: incorrect missing-PR message](artifacts/ui-audit-2026-10-09/evidence/github-http-error-hidden.txt). Fixed operation 934 shows HTTP 502. Unit coverage distinguishes the genuine missing-PR response from a backend failure and retains existing auth/remote classifications.

### B6: terminal border palette mismatch

Run `:colorscheme mono`, `warm`, or `cool`, then Ctrl-\ to open the terminal. Press Ctrl-W to unfocus it. Before the fix, these themes all used cyan focused borders, default grey unfocused borders, and the default floating background.

[Before: warm terminal](artifacts/ui-audit-2026-10-09/evidence/warm-terminal-before.txt). The fixed PTY matrix checks corners, horizontal rules, and both side rails in focused and unfocused states across **all ten built-in themes**, changing themes while hiding/reopening the same terminal session. Every palette passes. [After: warm terminal](artifacts/ui-audit-2026-10-09/evidence/warm-terminal-after.txt). The complete color values are in the archive's `terminal-theme-baseline.json` and `terminal-theme-fixed.json`.

## Compatibility gap and limits

**C1: `%` bracket matching is unsupported.** On `(one two)`, Vaayu leaves the cursor at 1:1; Vim moves it to 1:9. This command has no motion binding in Vaayu and is not listed among its documented motions. It is recorded as missing Vim functionality, separately from regressions in implemented commands. It remains unchanged; this audit does not establish complete Vim compatibility.

The GitHub CLI/API boundary used fixtures. Actual credentials, live network behavior, GitHub Enterprise deployments, and remote permissions were not exercised. Creating/reviewing/merging PRs and other GitHub writes are not implemented by this workspace and cannot be UI-tested here. Fixture error cases cover the UI's handling, not live authentication itself. Clipboard checks used isolated helpers rather than the user's desktop clipboard.

This is a bounded behavioral audit. It reports every reproducible bug found in these operations; it cannot prove that all possible bugs or every editor command have been tested.

## Verification and harness corrections

- All six bugs received targeted verification after the fix. The GitHub verification was split between the first four scenarios and a focused command/visual recheck to respect the operation limit.
- `cargo test --locked` in a clean checkout: **839 passed, 0 failed, 3 ignored for each of `vaayu` and `vy`**. The ignored tests are existing opt-in tests.
- `cargo fmt --all -- --check`, `cargo clippy --all-targets --locked -- -D warnings`, and `git diff --check` passed.
- Added five Rust regressions, `tests/pty_github_edges.py`, and `tests/pty_terminal_theme.py`; both new PTY scripts are included in CI.

Harness corrections are retained in the evidence rather than counted as product bugs: Vim Ex starts on the last line, so the reference commands were normalized with `gg0`; macro recording needed interactive Vim; pyte's default ANSI grey is `7f7f7f`; command mode displays the typed command instead of background messages, so its readiness check uses the fixture completion marker; and Vim's terminal capability queries required a VT100 reference terminal. An initial Rust run inherited `NO_COLOR` and repository-local ShaDa state; the clean checkout run removed those influences and passed.
